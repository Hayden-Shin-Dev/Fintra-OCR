# Fintra

**물류 증빙을 읽고, 거래의 차이를 확인하고, 검토조서까지 작성하는 AI 회계감사 보조 서비스입니다.**

[서비스 사용하기](https://hayden-shin-dev.github.io/Fintra-OCR/) | [설치 및 실행](docs/SETUP.md) | [추출 필드](SCHEMA.md) | [기술과 출처](SOURCES.md)

## 왜 만들었나요?

물류와 무역 거래를 검토할 때는 같은 거래의 정보가 여러 문서에 흩어져 있습니다. 상업송장의 금액, 포장명세서의 수량, 선하증권의 선적정보를 확인하고 장부와 맞춰 보는 데도 시간이 들지만, 차이를 발견한 뒤 근거를 찾아 검토 내용을 정리하는 작업도 반복됩니다.

Fintra는 이 과정을 하나의 화면에서 이어가려고 만들었습니다. 문서를 읽는 작업부터 비교 근거 확인, 추가 검토 사항 정리, 보고서 초안 작성까지 연결합니다. **반복되는 확인 작업은 줄이고, 사람이 판단해야 할 부분은 더 잘 보이게 하는 것**이 목적입니다.

## 이렇게 사용합니다

서비스에 접속해 회원가입한 뒤 새 검토를 시작하면 됩니다. 예시 자료로 먼저 사용해 볼 수도 있습니다.

| 단계 | 사용자가 하는 일 | Fintra가 하는 일 |
| --- | --- | --- |
| 1. 자료 업로드 | 같은 거래의 증빙과 필요한 경우 장부 CSV를 올립니다. | 문서를 읽고 비교에 필요한 필드를 추출합니다. |
| 2. 추출값 확인 | 원본과 추출값을 함께 보고 잘못 읽힌 값을 수정합니다. | 수정 이력과 원본 근거를 보존합니다. |
| 3. 거래 비교 | 불일치나 필수정보 누락을 확인하고 근거를 열어 봅니다. | 금액, 통화, 거래처, 날짜, 참조번호, 선적정보, 물류정보, 품목정보를 검토 영역별로 정리합니다. |
| 4. 보고서 작성 | 초안을 검토하고 내용을 수정한 뒤 저장합니다. | 검토조서 초안 작성과 PDF 저장을 지원합니다. |

문서끼리 비교하려면 **같은 거래의 서로 다른 증빙이 2종 이상** 필요합니다. 상업송장, 포장명세서, 선하증권을 함께 올리면 공통으로 기재된 항목을 더 넓게 확인할 수 있습니다. 한 장만 올려도 OCR 추출값은 확인할 수 있지만, 다른 문서와의 일치 여부는 판단할 수 없습니다.

장부는 선택사항입니다. **장부와 송장의 금액, 통화, 거래처, 거래일까지 비교하려면 장부 CSV와 상업송장을 함께 올려야 합니다.**

처음에는 업로드 화면의 샘플을 선택해 보세요.

- **샘플 A**: 장부와 증빙이 일치하는 경우
- **샘플 B**: 장부와 송장 금액이 다른 경우
- **샘플 C**: 포장명세서에 상품 수량이 없는 경우

## 비교 결과에서 끝나지 않도록

차이를 발견했을 때 숫자만 나열하면 다음에 무엇을 해야 하는지 알기 어렵습니다. Fintra에서는 비교값과 원본 근거를 함께 확인하고, 챗봇에 이어서 질문할 수 있습니다.

> “장부와 송장 금액이 다른데 어떤 리스크가 있어?”
>
> “이 차이를 확인하려면 어떤 자료가 필요해?”
>
> “이 결과로 검토 메모 초안을 작성해줘.”

챗봇은 질문과 관련된 거래 결과와 증빙을 조회해 답변을 구성합니다. 확인된 사실과 가능한 원인을 구분하고, 회계기준이 필요한 경우에는 검색한 문단의 관련성과 적용 조건을 확인하는 단계를 거칩니다.

일치 판정은 **제공된 자료와 비교 범위 안에서 값이 일치한다는 뜻**입니다. 거래 전체가 적정하다는 감사의견은 아닙니다. 검토조서도 사람이 근거와 내용을 확인하고 수정하는 초안으로 제공합니다.

## 어떻게 구현했나요?

문서 인식, 비교 판정, 설명 생성을 나눴습니다. AI가 문서를 읽고 설명을 작성하더라도, 비교 결과는 구조화된 데이터와 검토 규칙을 바탕으로 처리합니다.

| 구성 | 구현 방식 |
| --- | --- |
| 문서 인식 | PaddleOCR로 문자와 위치를 읽고, Qwen 모델을 이용해 문서 필드와 품목 정보를 구조화합니다. |
| 검토 규칙 | 정규화한 값을 비교하고 일치, 불일치, 필수정보 누락, 검토 대상 아님을 구분합니다. 반복되는 문서 간 비교는 검토 영역으로 묶습니다. |
| 대화 처리 | 질문의 주제와 요청 의도를 구분하고, 필요한 거래 결과와 증빙만 답변 문맥에 넣습니다. 후속 질문에서는 이전 대화와 관련 Finding을 이어서 사용합니다. |
| 회계기준 검색 | 기준서 번호와 문단을 지정하면 정확 조회를 먼저 수행합니다. 의미 기반 질문은 메타데이터 필터, 벡터 검색과 BM25, 재정렬을 거쳐 관련 문단을 선택합니다. |
| 근거 검증 | 검색 점수만으로 기준서를 붙이지 않고 거래 사실과 적용 조건을 확인합니다. 기준서, 질의회신, 내부 사례의 출처 유형을 구분합니다. |
| 보고서 | 비교 결과와 검토 내용을 바탕으로 편집 가능한 초안을 구성하고 ReportLab으로 PDF를 만듭니다. |
| 계정과 저장 | 로컬 SQLite에 계정을 저장하고 비밀번호는 scrypt로 해시합니다. 문서, 보고서, 대화와 검토 기록은 계정별로 접근을 제한합니다. |

웹 화면은 HTML, CSS, JavaScript로 만들었습니다. 안경 쓴 캐릭터는 Three.js로 렌더링합니다. OCR API는 Python과 FastAPI를 사용하고, 로컬 모델은 Ollama로 실행합니다. 모델 선택은 실행 설정으로 관리하며, 구성 예시는 Qwen3.5-9B를 사용합니다.

## 직접 실행하려면

**전체 웹 서비스**는 OCR, 거래 비교, 회계기준 검색을 연결하는 별도 Fintra 설치 런타임이 필요합니다. 모델 가중치와 검색 데이터는 이 저장소에 포함되어 있지 않습니다. 설치된 환경에서는 `studio/서버켜기.cmd`로 시작하고 `studio/서버끄기.cmd`로 종료합니다. 환경 설정과 실행 순서는 [실행 문서](docs/SETUP.md)에 정리했습니다.

**OCR 패키지만 실행**하려면 Python 3.10 이상과 Ollama를 준비한 뒤 저장소 루트에서 아래 명령을 실행합니다. 다음은 CPU 설치 예시입니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[ocr,ui,test,cpu]"
ollama pull qwen3.5:4b
.\.venv\Scripts\python launch_ui.py
```

공개 체험 링크는 현재 운영 PC의 로컬 서비스에 연결됩니다. PC와 서버가 실행 중일 때 사용할 수 있습니다.

## 저장소 구성

| 경로 | 내용 |
| --- | --- |
| `fintraocr/` | OCR 처리, 문서 필드 추출, 데이터 검증 |
| `studio/backend/` | 계정, 거래 검토, 챗봇, 회계기준 조회, 보고서 처리 |
| `studio/web/` | 업로드부터 보고서까지 이어지는 웹 화면 |
| `studio/tools/` | 서버 실행과 공유 링크 관리 |
| `examples/` | 실제 고객 자료를 사용하지 않는 합성 예제 |
| `tests/`, `studio/tests/` | OCR, 검토 규칙, 대화, 근거 검증, 계정 접근 제어 테스트 |

테스트 실행 방법과 필요한 로컬 자료는 [실행 문서의 테스트 항목](docs/SETUP.md#테스트)을 참고해 주세요. 업로드 문서, 계정 DB, 대화 기록, 모델 가중치와 회계기준 원문은 Git에 올리지 않습니다. 외부 패키지와 이미지의 출처는 [SOURCES.md](SOURCES.md)에 기록했습니다.
