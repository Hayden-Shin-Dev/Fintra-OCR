# Audit Field Schema v2

Audit Field Schema v2 is a field-scope and semantic-role contract. It is not
an extractor implementation and it does not change the frozen Gold or any
benchmark denominator.

## Scope

The schema separates identifiers, dates, parties, shipment/location, terms and
financial values, packing/weight values, and item-table values. In particular,
`buyer`, `consignee`, and `notify_party` remain distinct roles; invoice/B/L/L/C
identifiers remain distinct; and invoice, L/C, departure, arrival, and shipment
dates remain distinct.

Every document type receives a stable field structure. A field that is absent
or not semantically evidenced is represented as `null` by downstream
implementations; it is never filled from a nearby value merely because the
value has a compatible type.

## Generated artifacts

The schema and OCR-only scope audit are generated by:

```powershell
python .\scripts\build_audit_field_schema_v2.py --output-dir .\artifacts\fintra\schema-v2
```

The script reads only the existing Paddle OCR JSON in Accurate75, Fast300, and
v3 75 case caches. It does not call an extractor, modify Gold, or run OCR.

- `field_schema_v2.json`: machine-readable canonical contract.
- `label_synonyms.csv`: observed OCR label/title variants mapped to canonical fields.
- `field_ocr_coverage.csv`: label/value coverage estimate by dataset/document type/field.
- `cross_document_mapping.csv`: explicit audit reconciliation relationships.
- `schema_v1_vs_v2.csv`: current canonical field comparison.
- `semantic_collision_analysis.csv`: known role-collision risks and separation rules.

`estimated_recoverable` is an OCR-only proximity estimate. It is not field
accuracy and must not be used as a Gold or extractor score.

## Requirement levels

- `REQUIRED`: central to the document contract or audit operation.
- `AUDIT_USEFUL`: useful for reconciliation or review but not always present.
- `OPTIONAL`: accepted when present, not a completeness failure when absent.
- `NOT_APPLICABLE`: not part of that document type's contract.

The generated `inclusion_decision` additionally records whether frozen OCR
coverage is currently sufficient for development use or should be deferred.

## Cross-document principles

Cross-document links compare role-compatible fields only. For example,
`Commercial Invoice.seller`, `Packing List.exporter`, and `B/L.shipper` are
related audit roles but are not merged into one extractor field. Numeric and
date comparisons must use type-aware normalization; semantic role differences
are never normalized away.
